
# 🤝 ShareIt - java

**ShareIt** — Проектная деятельность.

Это бэкенд-приложение для шеринга вещей. Пользователи могут делиться своими вещами, брать их в аренду, создавать запросы на нужные вещи и отвечать на запросы других пользователей.

Проект демонстрирует навыки построения REST API, микросервисной архитектуры, работы с базами данных и следования принципам ООП и SOLID.

## 📌 Что реализовано

### 👤 Работа с пользователями
- Регистрация и обновление данных пользователей
- Просмотр информации о пользователях

### 📦 Работа с вещами
- Создание, обновление, просмотр вещей
- Поиск вещей по названию и описанию
- Управление статусом доступности вещи

### 📅 Работа с бронированиями
- Создание запроса на бронирование вещи
- Подтверждение или отклонение бронирования владельцем
- Просмотр бронирований пользователя (все, текущие, будущие, завершённые, отклонённые)

### 💬 Работа с запросами вещей
- Создание запроса на вещь, которую пользователь не может найти
- Просмотр своих запросов с ответами
- Просмотр запросов других пользователей
- Детальная информация о конкретном запросе

### 🔄 Ответы на запросы
- При создании вещи можно указать `requestId` — запрос, в ответ на который создаётся вещь
- Сохранение связи между вещью и запросом

### 💬 Комментарии
- Оставление отзывов на вещи после завершения бронирования

## 🏗 Архитектура (микросервисы)

Проект разделен на два модуля:

| Модуль | Порт | Назначение |
|--------|------|------------|
| **shareit-gateway** | `8080` | Входная точка, валидация запросов, масштабирование |
| **shareit-server** | `9090` | Бизнес-логика, работа с базой данных |

**Преимущества:** разделение ответственности, защита сервера от некорректных запросов, возможность масштабирования

## 🔗 API Эндпоинты

### Пользователи
- `POST /users` — создать пользователя
- `PATCH /users/{userId}` — обновить пользователя
- `GET /users/{userId}` — получить пользователя
- `DELETE /users/{userId}` — удалить пользователя

### Вещи
- `POST /items` — добавить вещь
- `PATCH /items/{itemId}` — обновить вещь
- `GET /items/{itemId}` — получить вещь
- `GET /items` — вещи пользователя
- `GET /items/search?text={text}` — поиск вещей

### Бронирования
- `POST /bookings` — создать бронирование
- `PATCH /bookings/{bookingId}` — подтвердить/отклонить
- `GET /bookings/{bookingId}` — получить бронирование
- `GET /bookings?state={state}` — бронирования пользователя
- `GET /bookings/owner?state={state}` — бронирования для владельца

### Запросы вещей
- `POST /requests` — создать запрос
- `GET /requests` — свои запросы с ответами
- `GET /requests/all` — запросы других пользователей
- `GET /requests/{requestId}` — детали запроса

### Комментарии
- `POST /items/{itemId}/comment` — оставить отзыв

## 💾 Работа с базой данных

### Что сделано:
- Спроектирована реляционная схема из 5 основных таблиц:
    - `users` — пользователи
    - `items` — вещи
    - `bookings` — бронирования
    - `requests` — запросы на вещи
    - `comments` — отзывы на вещи
- Настроены внешние ключи для обеспечения целостности данных
- Написаны JPQL-запросы для выборки данных со связями
- Использование Spring Data JPA для работы с репозиториями
- Настроена PostgreSQL для продакшена и H2 для тестов
